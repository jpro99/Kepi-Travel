## What happened

The previous prompt found `checkin-center` and `checkin-north` geometrically outside
`SEA_OSM_FOOTPRINTS.mainTerminal` via a point-in-polygon test, and flagged (but did not confirm)

## Most likely root cause — check this first

`seaFootprints.ts`'s own file comment says the real terminal has concourses that "radiate" from a
core — i.e. a genuinely non-convex, multi-armed shape. `mainTerminal` is a single closed ring
produced by Douglas-Peucker simplification (per the file header, generated by
`scripts/tmp-sea-import.mjs`). Collapsing a complex, multi-part building outline (likely originally
several OSM ways/multipolygon members) into one simplified ring is a common way to accidentally
produce a **self-intersecting polygon** — and a self-intersecting ring makes even a correct
point-in-polygon algorithm (turf's `booleanPointInPolygon` included) give unreliable results in the
areas near the crossing, which would explain exactly this symptom: two points "test" as inside while
visually landing outside.

**Step 1 — confirm or rule this out before touching any coordinates again:**

```ts
import kinks from "@turf/kinks";
import { polygon } from "@turf/helpers";

const ring = polygon([SEA_OSM_FOOTPRINTS.mainTerminal]);
const result = kinks(ring);
console.log("self-intersections found:", result.features.length);
```

If this reports any self-intersections, that is the real root cause — the ring itself is invalid,
and every point-in-polygon test run against it (past and future) is unreliable near those crossings.
Do not proceed to re-guess coordinates until this is resolved.

## If the ring is confirmed self-intersecting — how to fix it

- Regenerate `seaFootprints.ts` from the original Overpass output (`scripts/tmp-sea-import.mjs`)
  preserving the terminal as its true shape — if OSM's source data is a multipolygon or several
  disjoint/touching ways (main hall + concourse arms), do not force-merge them into one naive ring.
  Either keep them as a `MultiPolygon` (update `TerminalZonePolygon.ring` typing if needed — check
  `types.ts` first) or simplify each part separately before any union, not simplify-then-union.
- Re-run Douglas-Peucker simplification (if still needed for mobile performance) with a tolerance
  low enough that it doesn't collapse the concourse arms into self-crossing segments — validate
  with `@turf/kinks` after every simplification pass, not just once at the end.
- After the ring is confirmed valid (zero kinks), re-run the point-in-polygon check from the
  previous prompt against **all seven landside nodes** (`checkin-south`, `checkin-center`,
  `checkin-north`, `sec3-entry`, `sec3-exit`, `sec5-entry`, `sec5-exit`), not just the two flagged
  last time — a previously-"passing" node might turn out to be genuinely outside once the ring
  itself is trustworthy.
